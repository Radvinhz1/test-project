# ربات عکس و فیلم

برای یادگیری کد، [راهنمای آموزشی بخش‌به‌بخش](LEARNING.fa.md) را بخوان؛ نقش تمام فایل‌ها، تابع‌ها، ابزارها و آزمون‌ها را توضیح می‌دهد.

پروژهٔ پایتون برای ربات `@verySimpleUploaderbot` با پایگاه دادهٔ SQL Server.
مدیر عکس یا ویدئو را در گفت‌وگوی خصوصی می‌فرستد و برای هر فایل یک لینک دریافت می‌کند.
مخاطب لینک را باز می‌کند، در صورت نمایش دکمهٔ Start آن را می‌زند و فایل را دریافت می‌کند.

## سازوکار

- فایل روی تلگرام می‌ماند؛ شناسهٔ `file_id` و اطلاعات لینک در SQL Server ذخیره می‌شوند.
- کد لینک تصادفی و ۲۴ کاراکتری است. هر دارندهٔ لینک می‌تواند فایل را دریافت کند.
- فقط شناسه‌های عددی ثبت‌شده در `ADMIN_IDS` می‌توانند فایل ثبت یا لینک را غیرفعال کنند.
- نبودن مدیر باعث توقف اجرای عادی می‌شود؛ اولین مراجعه‌کننده خودکار مدیر نمی‌شود.
- اطلاعات هر ربات با شناسهٔ عددی همان ربات تفکیک می‌شوند.
- هر عضو یک آلبوم لینک مستقل دارد. توضیح فایل به صورت متن ساده حفظ می‌شود؛ قالب‌بندی آن حفظ نمی‌شود.
- برنامه فایل‌ها را دانلود، تبدیل یا اجرا نمی‌کند. تصویر و ویدئوی ارسال‌شده به شکل Document نیز با نوع رسانهٔ اعلام‌شده پذیرفته می‌شوند.

## ۱. دریافت کد روی ویندوز

اگر قبلاً همین مخزن را روی کامپیوتر داری، پوشهٔ آن را در VS Code باز کن.
در Terminal ابتدا وضعیت را بررسی کن:

```powershell
git status
git remote -v
```

باید remote مربوط به `Radvinhz1/test-project` باشد. اگر تغییرات ثبت‌نشده داری، آن‌ها را حفظ و ثبت کن؛ از دستورهای حذف تغییرات استفاده نکن.
سپس شاخهٔ این نسخه را دریافت کن:

```powershell
git fetch origin
git switch --track origin/feature/telegram-uploader
```

اگر شاخه از قبل روی کامپیوتر وجود دارد، فقط `git switch feature/telegram-uploader` را اجرا کن.
اگر مخزن را اصلاً دریافت نکرده‌ای، در پوشهٔ پروژه‌هایت اجرا کن:

```powershell
git clone --branch feature/telegram-uploader https://github.com/Radvinhz1/test-project.git
cd test-project
code .
```

مخزن خصوصی است؛ ممکن است گیت از تو بخواهد با حساب گیت‌هاب وارد شوی.

## ۲. ساخت پایگاه داده

در SSMS به آدرس زیر با Windows Authentication وصل شو:

```text
(localdb)\MSSQLLocalDB
```

روی New Query بزن و فایل `sql/create_database.sql` را اجرا کن؛ یا متن زیر را اجرا کن:

```sql
USE [master];
GO
IF DB_ID(N'TelegramUploader') IS NULL
BEGIN
    CREATE DATABASE [TelegramUploader];
END;
GO
```

این دستور پایگاه دادهٔ جداگانه می‌سازد. برنامه جدول `dbo.MediaFiles` را هنگام بررسی اتصال ایجاد می‌کند.
در Object Explorer روی Databases راست‌کلیک و Refresh کن تا نام پایگاه داده دیده شود.

## ۳. آماده‌سازی پایتون

پایتون ۳٫۱۰ به بالا لازم است؛ پایتون ۳٫۱۳ ویندوز برای این پروژه مناسب است.
در ترمینال PowerShell و داخل پوشهٔ پروژه اجرا کن:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

محیط مجازی، کتابخانه‌های این پروژه را از پروژه‌های دیگر جدا نگه می‌دارد.
با استفاده از مسیر کامل مفسر، نیازی به فعال کردن محیط یا تغییر Execution Policy نیست.
در VS Code از دستور `Python: Select Interpreter` مفسر داخل `.venv` را انتخاب کن تا ویرایشگر هم آن را بشناسد.

## ۴. درایور ارتباط با SQL Server

اتصال SSMS به تنهایی نصب بودن درایور موردنیاز پایتون را ثابت نمی‌کند.
درایورهای قابل استفاده را بررسی کن:

```powershell
.\.venv\Scripts\python.exe -c "import pyodbc; print(pyodbc.drivers())"
```

اگر `ODBC Driver 18 for SQL Server` در خروجی نیست، آن را از صفحهٔ رسمی مایکروسافت نصب کن:

https://learn.microsoft.com/en-us/sql/connect/odbc/download-odbc-driver-for-sql-server

معماری نصب باید با پایتون هماهنگ باشد؛ برای پایتون ۶۴ بیتی ویندوز از نصب‌کنندهٔ x64 استفاده کن.
اگر از قبل Driver 17 نصب داری، می‌توانی مقدار `SQL_DRIVER` را دقیقاً به `ODBC Driver 17 for SQL Server` تغییر بدهی.

## ۵. تنظیم اتصال محلی

یک بار فایل نمونه را کپی کن؛ اگر `.env` از قبل وجود دارد، آن را بازنویسی نکن:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

فایل `.env` را در ویرایشگر باز کن. مقدار `BOT_TOKEN` را با توکن واقعی BotFather جایگزین کن.
توکن را به چت، اسکرین‌شات یا گیت‌هاب نفرست. فایل `.env` در `.gitignore` قرار دارد.
تنظیمات SQL نمونه برای همان LocalDB آماده‌اند. گزینهٔ `SQL_ENCRYPT=no` برای اتصال محلی تنظیم شده است؛ برای سرور شبکه‌ای آن را به `yes` تغییر بده. فعلاً `ADMIN_IDS` خالی می‌ماند.

اتصال پایگاه داده را بررسی کن؛ این دستور توکن تلگرام یا شناسهٔ مدیر نمی‌خواهد:

```powershell
.\.venv\Scripts\python.exe bot.py --check-db
```

خروجی موفق:

```text
Database connection OK. dbo.MediaFiles is ready.
```

## ۶. تعیین مدیر

برنامه را در حالت راه‌اندازی اجرا کن:

```powershell
.\.venv\Scripts\python.exe bot.py --setup
```

در تلگرام وارد `@verySimpleUploaderbot` شو و دستور `/id` را بفرست.
این دستور شناسهٔ **حساب فرستنده** را نشان می‌دهد، نه شناسهٔ ربات.
برنامه را با Ctrl+C متوقف کن و عدد دریافتی را در `.env` قرار بده:

```dotenv
ADMIN_IDS=123456789
```

عدد بالا نمونه است؛ عدد واقعی حساب خودت را قرار بده. برای چند مدیر، شناسه‌ها را با ویرگول جدا کن.
در حالت راه‌اندازی هیچ‌کس نمی‌تواند فایل ثبت یا دریافت کند؛ این حالت به پایگاه داده هم وصل نمی‌شود.

## ۷. اجرای ربات و آزمون واقعی

```powershell
.\.venv\Scripts\python.exe bot.py
```

1. با حساب مدیر یک عکس کوچک و سپس یک ویدئوی کوتاه بفرست؛ برای هرکدام باید لینک دریافت کنی.
2. لینک‌ها را با یک حساب دیگر باز کن و در صورت نمایش Start آن را بزن؛ باید همان فایل دریافت شود.
3. با حساب دوم عکس بفرست؛ نباید اجازهٔ ثبت فایل داشته باشد.
4. برنامه را با Ctrl+C متوقف و دوباره اجرا کن؛ لینک قبلی باید همچنان کار کند.
5. از حساب مدیر دستور غیرفعال کردن را که همراه لینک آمده بفرست؛ سپس لینک را دوباره امتحان کن.

قالب دستور مدیر:

```text
/revoke CODE_FROM_LINK
```

غیرفعال کردن، دریافت‌های بعدی را متوقف می‌کند؛ فایل‌هایی را که قبلاً برای افراد ارسال شده‌اند حذف نمی‌کند.

## فایل‌ها و مسئولیتشان

| فایل | مسئولیت |
|---|---|
| `bot.py` | دستورها، دسترسی مدیر، دریافت فایل و ارسال پاسخ |
| `config.py` | خواندن و بررسی تنظیمات محلی |
| `database.py` | جدول‌ها و خواندن و نوشتن اطلاعات در SQL Server |
| `sql/create_database.sql` | ایجاد پایگاه دادهٔ جداگانه |
| `.env.example` | نمونهٔ تنظیمات بدون اطلاعات محرمانه |
| `requirements.txt` | نسخه‌های کتابخانه‌های موردنیاز |
| `tests/test_bot.py` | آزمون‌های آفلاین منطق ربات |

## عیب‌یابی

- **Encryption not supported on SQL Server:** کد شاخه را به‌روز کن. برای LocalDB مقدار `SQL_ENCRYPT=no` مناسب است. نسخهٔ جدید برای نام سروری که با `(localdb)\\` شروع می‌شود، در نبود این متغیر نیز رمزگذاری را الزامی نمی‌کند؛ سایر سرورها به‌صورت پیش‌فرض `yes` دارند. `TrustServerCertificate` به‌تنهایی این خطا را رفع نمی‌کند؛ آن گزینه مربوط به بررسی گواهی است.

- **SQL_DRIVER is not installed:** درایور ODBC را نصب یا نام دقیق درایور نصب‌شده را در `.env` وارد کن.
- **InterfaceError / OperationalError / ProgrammingError هنگام check-db:** نام سرور، وجود پایگاه دادهٔ TelegramUploader و ورود با همان حساب ویندوز را بررسی کن. اتصال موفق SSMS باید با تنظیمات همین فایل مطابقت داشته باشد.
- **InvalidToken:** توکن واقعی را در `.env` قرار بده؛ اگر قبلاً افشا شده، آن را از BotFather تعویض کن.
- **NetworkError / TimedOut:** برنامهٔ پایتون باید به سرویس تلگرام دسترسی شبکه داشته باشد. باز شدن خود اپ تلگرام الزاماً اتصال پایتون را ثابت نمی‌کند. اگر فقط اپ تلگرام پراکسی دارد، اتصال آن مستقل است.
- **Conflict:** فقط یک نسخه از برنامه برای یک توکن اجرا شود. نمونهٔ قبلی، حتی روی کامپیوتر دیگر، باید متوقف باشد.
- **ربات پاسخ نمی‌دهد:** ترمینال باید باز و برنامه در حال اجرا باشد. پس از تغییر `.env` برنامه را دوباره اجرا کن.
- **متن خطا کوتاه است:** برنامه عمداً متن خام خطا و آدرس درخواست‌های تلگرام را چاپ نمی‌کند تا توکن وارد گزارش نشود. نام خطا و مرحله‌ای که در آن رخ داده برای شروع عیب‌یابی کافی است.

## محدودهٔ این نسخه

این نسخه برای شروع و آزمایش محلی با تعداد درخواست کم است. اجرای شبانه‌روزی به میزبان همیشه روشن نیاز دارد.
LocalDB روی ویندوز و در حساب کاربری محلی اجرا می‌شود؛ برای استقرار روی سرور باید تنظیمات SQL Server و احراز هویت متناسب با میزبان آماده شوند.
در این نسخه از Windows Authentication استفاده می‌شود و ورود با نام کاربری و رمز SQL پیاده‌سازی نشده است.
مقدار `TrustServerCertificate=yes` برای اتصال محلیِ نمونه است؛ روی سرور گواهی معتبر و تنظیمات مناسب لازم است.
پشتیبان‌گیری از پایگاه داده ضروری است؛ اطلاعات لینک‌ها داخل گیت‌هاب ذخیره نمی‌شوند.
نسخهٔ اصلی رسانه‌ها را هم نگه دار؛ این ربات جای آرشیو پشتیبان فایل‌ها نیست.
محدودیت‌های ارسال تلگرام همچنان اعمال می‌شوند؛ برای حجم‌های موردنظر، ارسال مجدد را عملاً آزمایش کن.
آلبوم گروهی، تاریخ انقضا، عضویت اجباری، تبدیل ویدئو، آمار و کنترل حجم بالای درخواست هنوز پیاده‌سازی نشده‌اند.

## آزمون‌های آفلاین

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

این آزمون‌ها دسترسی مدیر، مسدود بودن حالت راه‌اندازی، نوع رسانه، لینک نامعتبر و لغو لینک را بررسی می‌کنند.
از مخزن داده و ارسال‌کنندهٔ آزمایشی استفاده می‌کنند و اتصال واقعی SQL Server یا تلگرام را ثابت نمی‌کنند.
آزمون واقعی روی کامپیوتر تو با مراحل بالا انجام می‌شود.
